# Обновление

Если вы переходите на новую мажорную версию, сгенерируйте новый конфигурационный файл последней версией Dispatch. Так вы увидите все новые настройки и при необходимости зададите их.

В остальном обновление сводится к трём шагам: поднять версию Dispatch \(вместе с ней обновятся и изменившиеся зависимости\), выполнить миграции данных и перезапустить все связанные сервисы.

:::info
В некоторых случаях перед обновлением стоит остановить сервисы, чтобы избежать случайных ошибок.
:::

## Обновление Dispatch {#upgrading-dispatch}

### Обновление пакета {#upgrading-the-package}

Проще всего обновить пакет Dispatch через `pip`:

```bash
uv pip install --upgrade dispatch
```

Возможно, вам удобнее ставить фиксированную версию, а не последнюю: так вы сами контролируете изменения.

Если вы устанавливаете из исходного кода, у вас могут появиться дополнительные неудовлетворённые зависимости, поэтому проверьте окружение, прежде чем браться за обновление.

### Выполнение миграций {#running-migrations}

Как и при первоначальной установке, миграции применяются командой обновления.

```bash
dispatch database upgrade
```

### Перезапуск сервисов {#restarting-services}

После обновления обязательно перезапустите _все_ сервисы Dispatch. Это необходимо, потому что Python загружает модули в память, и изменения кода не вступят в силу, пока сервисы не перезапущены.

К этим сервисам относятся:

- сервер — `dispatch server start`
- планировщик — `dispatch scheduler start`
