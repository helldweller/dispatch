# Проекты

Каждый кейс или инцидент в Dispatch привязан к проекту. Конфигурация проекта определяет, как создаются и ведутся кейсы и инциденты. Благодаря этому разные команды могут использовать Dispatch по-разному.

От собственных типов и приоритетов кейсов или инцидентов до отдельного представления метрик команды.

### Когда создавать новый проект, а когда использовать существующий? {#when-should-i-create-a-new-project-vs-using-an-existing-one}

Как правило, новый проект стоит создавать, когда команды почти не пересекаются в работе над кейсами или инцидентами.

Например, можно создать проект `security` для всех кейсов и инцидентов, связанных с безопасностью, и проект `reliability` для всех инцидентов, связанных с отказами.

**Название (Name):** название вашего проекта.

**Описание (Description):** описание вашего проекта.

**Цвет (Color):** цвет проекта, чтобы визуально отличать его от других проектов.

**Годовая стоимость сотрудника (Annual Employee Cost):** средняя годовая стоимость одного сотрудника.

**Рабочих часов в году (Business Year Hours):** число рабочих часов в году. Используется для расчёта почасовой ставки.

**Email владельца (Owner Email):** почтовый адрес владельца проекта.

**Канал обсуждения владельца (Owner Conversation):** канал обсуждения владельца проекта (например, канал Slack).
